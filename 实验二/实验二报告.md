## 二、可行性分析报告修订

### 2.1 修订内容概述

基于小组持续沟通与需求调研，在 V1.0 初稿基础上完成以下核心修订：

1. **需求细化与边界锁定**：基于5大核心功能模块，补全每个模块的功能要求、业务流程与验收标准，明确非功能需求与开发边界。
2. **文档结构合规化重构**：对齐国标 FAR 模板，补全缺失的标准章节，完善目录层级与编号规范。
3. **核心内容深度完善**：补充原有方案局限性分析、细化可选方案的对比维度与选择准则。
4. **CASE工具全流程融入**：新增CASE工具调研、选型与全流程应用方案，将工具应用纳入技术可行性论证。

### 2.2 修订后的可行性分析

> 完整修订版可行性分析报告见实验三文件夹（最终版）。

主要修订点：
- 补充了团队分工的具体职责说明
- 新增了技术风险与应对措施表
- 完善了经济可行性的效益分析
- 增加了项目跟踪与进度管理方案

## 三、CASE工具调研

### 3.1 调研分工

小组按软件工程全生命周期拆分调研模块：建模设计组、版本控制组、项目管理组、测试工具组、协作平台组。

| 工具分类 | 代表工具 | 核心用途 | 项目适配性 |
|----------|----------|----------|-----------|
| 建模设计类 | Microsoft Visio | 流程图、架构图、UML图绘制 | 商业付费，不适配 |
| 建模设计类 | Rational Rose | UML建模、模型驱动开发 | 已停止维护，不适配 |
| 建模设计类 | Sybase PowerDesigner | 数据库建模、业务流程建模 | 商业付费，不适配 |
| 建模设计类 | StarUML | UML全类型图绘制 | 开源免费，入选 |
| 建模设计类 | PlantUML | 文本驱动UML/架构图绘制 | 开源免费，与Git集成，入选 |
| 版本控制类 | Git | 分布式版本控制 | 开源免费，业界主流，入选 |
| 版本控制类 | CVS/SVN | 集中式版本控制 | 生态落后，不推荐 |
| 版本控制类 | ClearCase | 企业级配置管理 | 商业付费，不适配 |

### 3.3 项目最终CASE工具选型

| 项目阶段 | 选定工具 | 核心应用场景 |
|----------|----------|-------------|
| 项目启动 | Project Libre + 腾讯文档 | WBS任务分解、甘特图编制、文档协同 |
| 需求设计 | StarUML + PlantUML | 用例图、类图、时序图、架构图 |
| 开发协作 | Git + GitHub | 版本管理、分支开发、文档归档 |
| 开发调试 | VS Code | 前后端代码开发与调试 |
| 测试阶段 | Postman + Apache JMeter | 接口测试、性能测试 |

## 五、实验小结

本实验完成了可行性分析报告的修订和CASE工具的全面调研与选型。小组选择了 PlantUML + StarUML 进行建模设计，Git + GitHub 进行版本管理与协作，Postman 进行接口测试，Project Libre 进行项目管理。这些工具的选择充分考虑了项目的实际需求和团队的技术能力，为零成本、高效率的项目开发提供了支撑。
