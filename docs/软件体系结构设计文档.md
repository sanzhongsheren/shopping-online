## 3 体系结构设计

### 3.1 体系结构风格

#### 3.1.1 整体风格：分层架构

本系统采用**分层架构 (Layered Architecture)** 作为核心架构风格，共分为5层：

```
┌──────────────────────────────────────────────────┐
│          表示层 (Presentation Layer)              │
│      HTML + CSS + JavaScript + Bootstrap 5       │
│      位置：frontend/*                             │
├──────────────────────────────────────────────────┤
│          路由层 (Route Layer)                     │
│      Express Router——URL到处理函数的映射          │
│      位置：backend/routes/*                       │
├──────────────────────────────────────────────────┤
│          业务逻辑层 (Business Logic Layer)        │
│      Controllers——请求处理与业务编排             │
│      位置：backend/controllers/*                  │
├──────────────────────────────────────────────────┤
│          数据访问层 (Data Access Layer)           │
│      Models——数据库CRUD操作封装                  │
│      位置：backend/models/*                       │
├──────────────────────────────────────────────────┤
│          持久化层 (Persistence Layer)             │
│      MySQL 8.0 关系型数据库                       │
│      位置：database/*                             │
└──────────────────────────────────────────────────┘
```

**分层约束**：
- 上层可以调用下层，下层**不能**调用上层
- 跨层调用允许，但需显式声明
- 每层只暴露必要接口给上一层

**选择理由**：
1. 5人学生团队规模，分层架构简单易懂，学习成本低
2. Web应用的天然分层结构（浏览器→服务器→数据库）
3. 各层职责明确，不同成员可并行开发不同层

#### 3.1.2 辅助风格：MVC变体

| MVC角色 | 本项目对应 | 说明 |
|---------|-----------|------|
| Model | backend/models/ | 数据模型、数据库操作 |
| View | frontend/* (HTML/CSS/JS) | 前端页面 |
| Controller | backend/controllers/ + backend/routes/ | 请求处理与业务逻辑 |

#### 3.1.3 接口风格：RESTful API

前后端之间采用 RESTful 架构风格通信：

- **资源导向**：URL 表示资源（`/api/products`, `/api/orders`）
- **标准HTTP方法**：GET/POST/PUT/DELETE
- **无状态**：每次请求包含完整认证Token
- **统一响应格式**：JSON格式，`{ code, message, data }`

### 3.2 体系结构视图（4+1视图模型）

#### 3.2.1 逻辑视图——功能模块分解

系统从逻辑上划分为7个功能模块：

```
用户管理 → 商品管理 → 购物车 → 订单管理 → 审核管理 → 留言 → 收藏
```

**模块间依赖关系**：用户管理为基础模块；商品管理依赖用户管理；订单管理依赖用户管理+商品管理+购物车；审核管理依赖用户管理+商品管理。

#### 3.2.2 开发视图——代码组织结构

```
shopping-online-main/
├── frontend/                  # 前端
│   ├── index.html
│   ├── css/style.css
│   ├── js/ (main.js, api.js, utils.js)
│   └── pages/ (login, product-list, product-detail, cart, checkout, order, audit, user-profile, messages)
├── backend/                   # 后端 Node.js + Express
│   ├── app.js
│   ├── config/ (db.js, auth.js)
│   ├── routes/ (users, products, orders, cart, audit, messages, favorites)
│   ├── controllers/ (对应的7个controller)
│   ├── models/ (对应的7个model)
│   ├── middleware/ (auth.js, validator.js)
│   └── utils/ (response.js)
├── database/                  # 数据库
│   ├── init.sql
│   ├── seed.sql
│   └── README.md
└── docs/                      # 项目文档
```

#### 3.2.3 进程视图——运行时模型

```
Browser (多实例) → HTTP Request → Node.js Express (单进程, Event Loop) → SQL Query → MySQL DB
                                    ← JSON Response                      ← Result Set
```

**运行时特征**：
- Node.js 事件循环单线程处理并发
- 中间件链：CORS → JSON Parse → Auth → Route → Controller → Model → DB
- 数据库连接池：mysql2/pool，最大连接数10
- 无状态：JWT Token 携带认证信息

#### 3.2.4 物理视图——部署拓扑

```
客户端PC (Chrome/Edge/Firefox)
    │ HTTP :3000
    ▼
服务器PC (Node.js Express :3000)
    │ SQL :3306
    ▼
数据库服务器 (MySQL 8.0 :3306)
```

开发环境所有组件运行在同一台PC上；生产环境可选Nginx反向代理+HTTPS。

#### 3.2.5 场景视图——用户下单场景

```
买家 → 登录 → 浏览商品 → 加入购物车 → 结算 → 选择地址 → 确认下单
                                                          │
Route: POST /api/orders (authenticate + authorizeRoles("buyer"))
    │
Controller: orderController.createOrder()
  ├── 参数校验：items、addressId、paymentMethod
  ├── 计算总金额
  ├── 生成订单号：ORD + YYYYMMDD + 6位序号
  ├── 开启事务 → 创建订单 → 创建明细(商品快照) → 更新库存 → 清空购物车
  └── 返回订单信息
```

### 3.3 关键设计决策

| 决策ID | 决策内容 | 理由 | 影响 |
|--------|----------|------|------|
| AD-01 | 采用分层架构 | 团队小、易理解、Web应用匹配 | 各层独立演进，简化分工 |
| AD-02 | Express作为后端框架 | 入门快、生态丰富 | 学习成本低 |
| AD-03 | JWT无状态认证 | 前后端分离场景天然适合 | 每次请求携带Token |
| AD-04 | 前后端分离(REST API) | 支持独立开发 | 需处理CORS |
| AD-05 | 不使用ORM，直接SQL | SQL透明可控，降低学习成本 | 查询灵活，代码量稍大 |
| AD-06 | Routes→Controllers→Models三层 | 关注点分离 | 维护性提高 |
| AD-07 | 订单使用商品快照 | 防止商品变更影响历史订单 | 数据冗余可接受 |
| AD-08 | 密码bcrypt加密 | 业界安全标准 | 哈希计算开销可接受 |

### 3.4 接口设计

#### 3.4.1 前端-后端接口（REST API）

**基础URL**：`http://localhost:3000/api`

**公开接口**：

| 方法 | 端点 | 说明 |
|------|------|------|
| POST | `/users/register` | 用户注册 |
| POST | `/users/login` | 用户登录 |
| GET | `/products` | 商品列表（分页/搜索/排序） |
| GET | `/products/:id` | 商品详情 |
| GET | `/products/categories` | 分类列表 |
| GET | `/messages` | 留言列表 |

**需认证接口**（Header: `Authorization: Bearer <token>`）：

| 方法 | 端点 | 角色 | 说明 |
|------|------|------|------|
| GET | `/users/profile` | 所有 | 个人信息 |
| PUT | `/users/profile` | 所有 | 更新信息 |
| GET/POST | `/users/addresses` | 所有 | 地址管理 |
| PUT/DELETE | `/users/addresses/:id` | 所有 | 地址操作 |
| POST | `/products` | seller | 发布商品 |
| PUT/DELETE | `/products/:id` | seller | 管理商品 |
| GET/POST | `/cart` | buyer | 购物车 |
| PUT/DELETE | `/cart/:id` | buyer | 购物车操作 |
| POST | `/orders` | buyer | 创建订单 |
| GET | `/orders` | 所有 | 订单列表 |
| GET | `/orders/:id` | 所有 | 订单详情 |
| PUT | `/orders/:id/status` | 所有 | 状态更新 |
| PUT | `/orders/:id/cancel` | buyer | 取消订单 |
| GET/POST | `/audits` | admin | 审核管理 |
| PUT | `/audits/:id` | admin | 审核处理 |
| POST | `/messages` | 所有 | 发送留言 |
| DELETE | `/messages/:id` | 所有 | 删除留言 |
| GET/POST | `/favorites` | buyer | 收藏管理 |

**统一响应格式**：
```json
{ "code": 200, "message": "success", "data": {...} }
{ "code": 400, "message": "请求参数错误" }
{ "code": 401, "message": "未登录或Token已过期" }
{ "code": 403, "message": "权限不足" }
```

#### 3.4.2 后端-数据库接口

通过 `mysql2/promise` 连接池：

```js
const pool = mysql.createPool({
  host: 'localhost', user: 'root',
  database: 'online_shopping', charset: 'utf8mb4'

```

### 3.5 数据架构

| 策略项 | 选择 | 说明 |
|--------|------|------|
| 数据库 | MySQL 8.0 | 关系型，适合电商交易 |
| 字符集 | utf8mb4 | 支持完整Unicode |
| 存储引擎 | InnoDB | 事务、行级锁、外键 |
| ORM | 不使用 | 直接SQL，利用mysql2驱动 |

**事务保障**（订单创建关键操作）：
```sql
START TRANSACTION;
INSERT INTO orders ... ;
INSERT INTO order_items ... ;
UPDATE products SET stock = stock - ? WHERE product_id = ?;
DELETE FROM cart WHERE user_id = ? AND product_id IN (...);
COMMIT; -- 任一失败则 ROLLBACK
```

### 3.6 安全架构

#### 3.6.1 认证机制（JWT）

- 登录验证用户名+密码 → 生成JWT（含userId, username, role，24h有效）→ 返回客户端
- 后续请求携带 `Authorization: Bearer <token>`
- `authenticate` 中间件验证Token

#### 3.6.2 授权机制（基于角色）

```
          │ 浏览商品 │ 发布商品 │ 创建订单 │ 发货 │ 审核 │
buyer     │   ✅    │   ❌    │   ✅    │ ❌  │ ❌  │
seller    │   ✅    │   ✅    │   ❌    │ ✅  │ ❌  │
admin     │   ✅    │   ❌    │   ❌    │ ❌  │ ✅  │
```

实现：`authorizeRoles(...roles)` 中间件，rest参数设计支持任意角色扩展。

#### 3.6.3 数据安全

| 措施 | 实现方式 |
|------|----------|
| 密码加密 | bcrypt哈希（salt rounds=10） |
| SQL注入防护 | 参数化查询 `db.execute(sql, params)` |
| XSS防护 | 前端输出转义 |
| 输入校验 | `middleware/validator.js` |

## 附录B：架构决策记录（ADR）

### ADR-001: 选择Express

- **背景**：需选择后端框架
- **决策**：Express（非SpringBoot/Django）
- **理由**：前后端统一JavaScript，社区庞大，适合中小项目
- **后果**：需额外引入ORM替代和校验中间件

### ADR-002: 不使用ORM

- **背景**：需选择数据库访问方式
- **决策**：直接参数化SQL（非Sequelize等ORM）
- **理由**：降低学习曲线，SQL透明适合教学项目
- **后果**：缺少对象映射便利性

### ADR-003: JWT无状态认证

- **背景**：需选择认证方案
- **决策**：JWT（非Session/Cookie）
- **理由**：前后端分离天然适合JWT，无需服务器存储会话
- **后果**：Token无法主动失效（V1.0不实现黑名单）
