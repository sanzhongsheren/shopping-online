## 1 引言

### 1.1 目的

本文档旨在全面、准确地描述**商品网上交易系统**的软件需求，包括系统的功能需求、非功能需求、外部接口需求及约束条件等。本文档的编写遵循 IEEE 830-1998《软件需求规格说明书推荐实践》标准，作为系统设计、开发实现、测试验收及项目管理的依据。

本文档的目标是：
- 明确系统的功能范围和行为特征，为设计和开发团队提供统一的指导；
- 定义系统与外部环境的接口，确保各模块间的协调一致；
- 作为需求确认和变更控制的基线文档；
- 为后续的概要设计、详细设计、测试计划和用户手册提供基础。

### 1.2 文档约定

**需求标识符格式**：
- 功能需求以 `FR-` 为前缀，后跟模块缩写和序号，例如 `FR-USER-01`。
- 非功能需求以 `NFR-` 为前缀，后跟类别缩写和序号，例如 `NFR-PERF-01`。
- 接口需求以 `IR-` 为前缀，后跟接口类型缩写和序号。

**优先级定义**：
- **高**：核心功能，必须在第一版中实现，缺失则系统不可用。
- **中**：重要功能，应在正式发布前完成。
- **低**：增强功能，可在后续版本中实现。

### 1.4 产品范围

**商品网上交易系统**是一个基于B/S架构的轻量级电子商务平台，旨在为买家和卖家提供便捷、安全的在线交易服务。系统支持三种用户角色：**买家**、**卖家**和**管理员**，覆盖用户注册登录、商品发布与浏览、购物车管理、订单流转、商品与用户审核、留言互动等全流程交易环节。

本系统作为软件工程课程实践项目，限于课程学期内（2–3个月）完成开发，定位为课程演示级别系统，不支持高并发商用场景。

系统目标：
1. 实现**用户管理、商品管理、审核管理、购物下单、订单管理**五大核心模块；
2. 采用前后端分离架构，基于 RESTful API 进行数据交互；
3. 交付可运行系统并配套完整软件工程文档；
4. 界面规范、功能完整、操作简便，模拟真实电商平台的核心流程。

## 2 总体描述

### 2.1 产品前景

#### 2.1.1 产品背景

随着互联网技术的普及和电子商务的快速发展，线上交易已成为人们日常生活的重要组成部分。然而，在校园环境和小型社区中，仍存在商品交易信息不透明、交易流程不规范、缺乏统一管理平台等问题。本系统针对上述痛点，开发一套适用于小型社区环境的轻量化网上交易系统，实现从商品发布、审核、浏览、下单到交易完成的全流程闭环管理。

#### 2.1.2 业务机遇

- 为校园内闲置物品交易提供规范的线上平台；
- 帮助小型卖家建立商品展示和销售渠道；
- 通过审核机制保障交易安全和商品质量。

#### 2.1.3 系统定位

本系统定位为**课程教学实践项目**，兼顾功能完整性和技术可行性，在有限资源下实现电商系统的核心业务流程。

### 2.2 产品功能

系统主要功能分为以下七大模块：

**1. 用户管理模块**
- 用户注册（买家/卖家角色选择，卖家需填写身份信息）
- 用户登录（支持角色选择登录）
- 用户信息查看与编辑（头像、联系方式等）
- 地址管理（添加、编辑、删除收货地址，设置默认地址）

**2. 商品管理模块**
- 商品发布（卖家填写商品名称、描述、价格、库存、分类、图片等）
- 商品编辑（卖家修改已发布商品信息）
- 商品浏览（买家浏览商品列表，支持分类筛选）
- 商品搜索（按关键词搜索商品）
- 商品排序（按销量、价格、发布时间排序）
- 商品详情查看（展示商品信息、卖家信息、商品留言）

**3. 购物车模块**
- 添加商品到购物车
- 修改购物车中商品数量
- 从购物车中删除商品
- 清空购物车

**4. 订单管理模块**
- 创建订单（买家从购物车或直接购买下单）
- 订单状态流转（待支付 → 已支付 → 已发货 → 已收货 → 已完成）
- 取消订单（待支付状态下可取消）
- 订单详情查看
- 订单列表查看
- 卖家发货操作
- 买家确认收货操作

**5. 审核管理模块**
- 卖家注册资质审核（管理员审核卖家提交的身份信息）
- 商品发布审核（管理员审核新发布的商品是否合规）
- 商品编辑后重新审核
- 审核列表查看（待审核/已审核/已拒绝）

**6. 留言模块**
- 对商品进行留言
- 留言回复（树形结构）
- 留言查看

**7. 收藏模块**
- 添加商品到收藏夹
- 取消收藏
- 查看收藏列表
- 检查收藏状态

### 2.3 用户特征

| 用户角色 | 特征描述 | 使用频率 | 专业知识水平 |
|----------|----------|----------|-------------|
| 买家 | 浏览和购买商品的普通用户。需要注册登录后使用购物车、下单等功能。主要关注商品搜索、浏览体验和购买流程的便捷性。 | 中高频 | 低——普通互联网用户即可使用 |

## 3 具体需求

### 3.1 外部接口需求

#### 3.1.1 用户界面

系统采用 B/S 架构，所有功能通过浏览器访问。界面设计遵循以下原则：

- **响应式布局**：基于 Bootstrap 5 框架，适配桌面端主流分辨率（1366×768 及以上）。
- **统一风格**：保持页面整体视觉风格一致，包括颜色体系、字体、按钮样式、卡片样式等。
- **操作反馈**：关键操作（登录、注册、下单、审核等）通过 Toast 通知、模态框等方式给用户即时反馈。
- **确认机制**：涉及数据删除、状态变更等敏感操作时，采用确认对话框防止误操作。

**页面清单**：

| 页面 | 路由 | 角色 | 功能描述 |
|------|------|------|----------|
| 首页 | `index.html` | 所有 | 商品分类导航、轮播推荐、热销商品展示 |
| 登录/注册 | `pages/login.html` | 所有 | 用户登录与注册（含角色选择） |
| 商品列表 | `pages/product-list.html` | 所有 | 商品搜索、分类筛选、排序、分页 |
| 商品详情 | `pages/product-detail.html` | 所有 | 商品详情展示、数量选择、购物车/购买/收藏操作、留言区 |
| 购物车 | `pages/cart.html` | 买家 | 购物车商品管理、下单入口 |
| 结算页 | `pages/checkout.html` | 买家 | 订单确认、地址选择、提交订单 |
| 订单列表 | `pages/order.html` | 所有 | 订单列表查看（按角色显示不同状态） |
| 审核管理 | `pages/audit.html` | 管理员 | 用户审核、商品审核 |
| 用户信息 | `pages/user-profile.html` | 所有 | 个人信息编辑、地址管理 |
| 留言消息 | `pages/messages.html` | 所有 | 留言列表与管理 |

#### 3.1.2 硬件接口

本系统无直接硬件接口需求，运行于标准 PC 硬件环境。

#### 3.1.3 软件接口

**接口概览**：

| 商品 | GET | `/api/products/categories` | 分类列表 |
| 商品 | POST | `/api/products` | 添加商品（卖家） |
| 商品 | PUT | `/api/products/:id` | 更新商品 |
| 商品 | DELETE | `/api/products/:id` | 删除商品 |
| 购物车 | GET | `/api/cart` | 获取购物车 |
| 购物车 | POST | `/api/cart` | 添加至购物车 |
| 购物车 | PUT | `/api/cart/:id` | 更新购物车数量 |
| 购物车 | DELETE | `/api/cart/:id` | 删除购物车项 |
| 购物车 | DELETE | `/api/cart` | 清空购物车 |
| 订单 | POST | `/api/orders` | 创建订单 |
| 订单 | GET | `/api/orders` | 订单列表 |
| 订单 | GET | `/api/orders/:id` | 订单详情 |
| 订单 | PUT | `/api/orders/:id/status` | 更新订单状态 |
| 订单 | PUT | `/api/orders/:id/cancel` | 取消订单 |
| 审核 | GET | `/api/audits` | 审核列表 |
| 审核 | POST | `/api/audits` | 提交审核 |
| 审核 | PUT | `/api/audits/:id` | 审核处理 |
| 留言 | GET | `/api/messages` | 获取留言 |
| 留言 | POST | `/api/messages` | 发送留言 |

| 收藏 | GET | `/api/favorites` | 获取收藏列表 |

| 收藏 | GET | `/api/favorites/check/:id` | 检查收藏状态 |

##### 3.1.3.2 后端与数据库接口

后端通过 MySQL 数据库驱动连接数据库，执行 SQL 语句进行数据操作。

- **数据库名称**：`online_shopping`
- **字符集**：`utf8mb4`
- **连接方式**：通过配置文件 `backend/config/db.js` 管理数据库连接参数。
- **ORM/驱动**：Node.js MySQL 驱动（mysql2 或类似）。

#### 3.1.4 通信接口

- **协议**：HTTP/1.1（开发环境），建议生产环境使用 HTTPS。
- **数据格式**：请求与响应均采用 `application/json`。
- **响应格式**：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { ... }
}
```

- **错误响应**：

```json
{
  "code": 400,
  "message": "错误描述信息",
  "errors": []
}
```

- **分页参数**：`page`（页码）、`page_size`（每页条数），响应中返回 `total`（总条数）。

### 3.2 功能需求

#### 3.2.1 用户管理模块

| 需求ID | 需求描述 | 优先级 |
|--------|----------|--------|
| FR-USER-01 | 用户注册：用户可注册为买家或卖家角色。注册时需提供用户名（4-20位字母或数字）、密码（至少6位），可选提供邮箱和手机号。卖家注册需额外填写真实姓名和身份证号。 | 高 |
| FR-USER-02 | 用户名唯一性校验：系统确保注册的用户名在数据库中唯一，重复时给出提示。 | 高 |

### 4.1 术语定义

| 术语 | 定义 |

| B/S 架构 | Browser/Server 架构，浏览器/服务器模式 |

| CRUD | Create/Read/Update/Delete，增删改查基本操作 |
| Toast | 一种轻量级消息提示组件 |
| 商品快照 | 订单生成时保存的商品信息副本，防止后续变更影响已有订单 |

### 4.2 用例模型

系统包含三个角色，共 18 个主要用例：

**买家用例**：
1. 注册——买家可注册为系统用户
2. 登录——买家可登录系统
3. 浏览商品——买家可浏览商品列表
4. 搜索商品——买家可按关键词搜索商品
5. 加入购物车——买家可将商品加入购物车
6. 下订单——买家可通过购物车或直接购买创建订单
7. 确认收货——买家可确认收到商品
8. 留言——买家可对商品留言

**卖家用例**：
9. 登录——卖家登录系统（卖家需注册并通过审核）
10. 发布商品——卖家可发布新商品
11. 编辑商品——卖家可编辑已发布商品
12. 查看订单——卖家可查看与自己商品相关的订单
13. 发货——卖家可修改订单状态为已发货

**管理员用例**：
14. 登录——管理员登录后台
15. 审核用户——管理员审核卖家注册申请
16. 审核商品——管理员审核新发布或编辑后的商品
17. 管理订单——管理员可查看和管理所有订单
