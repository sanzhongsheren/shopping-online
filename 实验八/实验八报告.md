## 一、Petri网建模

### 1.1 Petri网基本概念

Petri网是一种用于描述和分析离散事件动态系统的图形化数学工具，由 Carl Adam Petri 在1962年提出。Petri网特别适合建模并发、同步、冲突、互斥等系统行为。

**基本元素**：
- **库所(Place, P)**：用圆圈表示，表示系统的状态或条件
- **变迁(Transition, T)**：用方框或粗线表示，表示事件或操作
- **弧(Arc)**：连接库所和变迁的有向边，表示状态与事件的因果关系
- **令牌(Token)**：用库所中的黑点表示，表示系统当前状态
- **初始标识(M0)**：系统的初始令牌分布

**变迁触发规则**：
1. 若变迁的所有输入库所中至少有一个令牌，则该变迁是**使能的(enabled)**
2. 使能的变迁可以**触发(fire)**：从每个输入库所消耗一个令牌，向每个输出库所产生一个令牌

### 1.2 订单状态流转的Petri网模型

针对本系统的核心业务流程——订单状态流转，建立Petri网模型：

```
库所(P)：
  P0: 购物车中有商品
  P1: 订单已创建(待支付)
  P2: 订单已支付
  P3: 订单已发货
  P4: 订单已收货
  P5: 订单已完成
  P6: 订单已取消
  P7: 用户令牌(代表买家在线)
  P8: 卖家令牌(代表卖家在线)

变迁(T)：
  T0: 用户提交订单
  T1: 用户支付
  T2: 卖家发货
  T3: 用户确认收货
  T4: 系统自动完成
  T5: 用户取消订单
```

**Petri网图形表示**（文本描述）：

```
    P7 ──→ T0 ←── P0
             │
             ↓
           [P1] ──→ T1 ──→ [P2] ──→ T2 ←── P8
             │                         │
             │                         ↓
             │                       [P3] ──→ T3 ──→ [P4] ──→ T4 ──→ [P5]
             │
             └──→ T5 ──→ [P6]
```

**订单流转过程**：
1. 买家(P7)从购物车(P0)提交订单(T0)，产生待支付订单(P1)
2. 买家支付(T1)，订单进入已支付状态(P2)
3. 卖家(P8)发货(T2)，订单进入已发货状态(P3)
4. 买家确认收货(T3)，订单进入已收货状态(P4)
5. 系统自动完成(T4)，订单进入已完成状态(P5)
6. 在待支付(P1)阶段，买家可取消订单(T5)，进入已取消状态(P6)

**可达性分析**：
- 从初始状态(令牌在P0, P7, P8)，可达到所有状态
- 死锁检查：无死锁——每个状态都有后继变迁（P5为终止状态，P6为终止状态）
- 有界性：每个库所最多容纳1个令牌，Petri网是1-安全的

## 四、OCL逻辑约束

对象约束语言（Object Constraint Language, OCL）用于在UML模型中表达精确的约束条件。

### 4.1 订单创建约束

```
-- 创建订单时，购物车不能为空
context Order::createOrder(buyerId: Integer)
  pre: cart->select(c | c.userId = buyerId)->notEmpty()
  
-- 订单总金额必须等于各明细小计之和
context Order
  inv: totalAmount = items->collect(subtotal)->sum()
  
-- 订单状态必须在定义的状态集合中
context Order
  inv: status <> null and Set{'pending_payment','paid','shipped','received','completed','cancelled'}->includes(status)
```

### 4.2 商品状态约束

```
-- 只有已审核的商品才能上架销售
context Product
  inv: status = #onsale implies audit->exists(a | a.auditType = #product_publish and a.status = #approved)
  
-- 商品价格必须大于0
context Product
  inv: price > 0
  
-- 商品库存必须非负
context Product
  inv: stock >= 0
```

### 4.3 用户角色约束

```
-- 管理员不能被删除
context User
  inv: role = #admin implies status <> #deleted
  
-- 卖家必须提供真实姓名和身份证号
context User::register()
  pre: role = #seller implies (realName <> null and idCard <> null)
```

## 六、实验小结

本实验学习了Petri网的基本理论和建模方法，使用Petri网对订单状态流转进行了形式化建模。同时运用状态图（订单状态机、商品审核状态机）、数据流图（DFD）和OCL对象约束语言等多种动态建模工具，从不同角度对系统进行了完整建模。通过这些动态建模工具，更精确地描述了系统的行为特征和业务规则，为完善SRS提供了坚实支撑。
