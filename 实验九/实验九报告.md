## 一、UML深入理解

### 1.1 UML概述

统一建模语言（Unified Modeling Language, UML）是一种通用的可视化建模语言，用于软件系统的规格说明、可视化、构造和文档化。UML 2.0包含14种图，分为两大类：

#### 结构图（Structure Diagrams）
| 图类型 | 用途 | 本项目应用 |
|--------|------|-----------|
| 类图 | 描述类及其关系 | ✅ 系统领域模型类图 |
| 对象图 | 描述特定时刻的对象实例 | 用于说明关键数据结构 |
| 组件图 | 描述系统组件及依赖 | 后端模块依赖关系 |
| 部署图 | 描述系统物理部署 | ✅ 系统部署架构图 |
| 包图 | 描述包之间的依赖 | 前后端代码模块组织 |
| 组合结构图 | 描述类的内部结构 | — |
| 剖面图 | 描述UML扩展机制 | — |

#### 行为图（Behavior Diagrams）
| 图类型 | 用途 | 本项目应用 |
|--------|------|-----------|
| 用例图 | 描述系统功能和角色 | ✅ 系统用例图 |
| 活动图 | 描述业务流程和控制流 | ✅ 审核活动图 |
| 状态机图 | 描述对象生命周期 | ✅ 订单状态图 |
| 顺序图 | 描述对象间交互的时间顺序 | ✅ 购物与配送时序图 |
| 通信图 | 描述对象间的协作关系 | — |
| 时间图 | 描述时间约束 | — |
| 交互概览图 | 活动图与顺序图的结合 | — |

### 1.2 UML在项目中的实践总结

本项目采用了以下6种UML图进行系统建模：

1. **用例图**：描绘3种角色（买家/卖家/管理员）与18个用例的关系
2. **类图**：展示10个核心数据实体及其关联关系
3. **部署图**：展示B/S架构下的前端-后端-数据库三层部署结构
4. **状态图**：描述订单（6个状态）和商品审核（4个状态）的状态流转
5. **活动图**：描述管理员审核流程的业务活动和控制流
6. **顺序图**：描述用户下单到收货的时间序列交互过程

> 所有UML图的PlantUML源文件和导出图片见项目 `docs/UML/` 目录。

## 二、计算机学科中的逻辑

### 2.1 逻辑在软件工程中的应用

计算机学科中的逻辑主要包括：

| 逻辑类型 | 主要应用 | 本项目的关联 |
|----------|----------|-------------|
| 命题逻辑 | 程序条件判断、布尔表达式 | 后端权限校验逻辑（基于角色的if-else判断） |
| 一阶谓词逻辑 | 数据库查询、形式化需求规约 | SQL查询条件、OCL约束表达 |
| 时态逻辑 | 并发系统验证、状态转换验证 | 订单状态流转规则的形式化验证 |
| 霍尔逻辑 | 程序正确性证明、前后条件验证 | API接口的输入输出契约 |
| 模态逻辑 | 系统行为推理、安全协议分析 | 权限模型的形式化推理 |

### 2.2 逻辑在本项目的实际应用

**1. 权限控制的逻辑表达**

系统权限模型可以用一阶谓词逻辑表达：

```
∀ user ∈ Users, resource ∈ Resources:
  canAccess(user, resource) ↔
    (user.role = 'buyer' ∧ resource.owner = user) ∨
    (user.role = 'seller' ∧ resource.owner = user) ∨
    (user.role = 'admin')
```

**2. 状态转换的时态逻辑约束**

```
G(pending_payment → X(paid ∨ cancelled))  // 总是：待支付状态的下一个状态只能是已支付或已取消
G(paid → X(shipped))                        // 总是：已支付状态的下一个状态是已发货
G(shipped → X(received))                    // 总是：已发货状态的下一个状态是已收货
```

**3. API接口的前后条件**

```
{pre: username不为空 ∧ password长度≥6}
注册接口执行
{post: 数据库中新增一条用户记录 ∨ 返回错误信息}
```

## 三、SAD初稿——软件体系结构设计文档

### 3.1 SAD标准对比

#### GB/T 8567-2006 软件(结构)设计说明(SDD)

国标SDD文档要求包含以下主要内容：
- 引言（标识、系统概述、文档概述）
- 引用文件
- CSCI级设计决策
- CSCI体系结构设计（CSCI部件、执行概念、接口设计）
- CSCI详细设计（部件详细设计、接口详细设计）

#### IEEE 42010-2011 软件架构描述(SAD)

IEEE 42010标准关注：
- 架构描述的多视图方法
- 利益相关者关注点
- 架构视图与视点的概念
- 架构决策和基本原理

## 四、经典软件体系结构案例研究

### 4.1 Parnas模块化分解标准

学习 David Parnas 的经典论文《On the Criteria To Be Used in Decomposing Systems into Modules》，理解模块化设计的关键标准：

| 设计准则 | 说明 | 本项目体现 |
|----------|------|-----------|
| 信息隐藏 | 每个模块隐藏一个可能变化的设计决策 | 数据库字段变化不影响控制器代码 |
| 接口最小化 | 模块只暴露必要的接口 | 模型层只导出数据访问函数 |
| 高内聚 | 模块内元素紧密相关 | 每个Controller只处理一个业务域 |
| 低耦合 | 模块间依赖尽可能少 | 路由-控制器-模型之间通过函数调用解耦 |

### 4.2 KWIC案例初步了解

KWIC（Key Word In Context）是软件体系结构教材中的经典案例。它主要解决一个问题：给定一组文本行，生成所有行的循环移位并按字母顺序排序。
